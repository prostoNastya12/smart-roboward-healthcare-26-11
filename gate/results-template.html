How to read this table

  • Unauthorized blocked (for example for M0): we sent 10 attack requests. The number is how many were stopped before the robot moved or any patient data leaked. For M0, of the 10 attacks reached the robot, so only was blocked. For M1, of 10 were blocked. Higher is better; 10/10 means every attack was stopped.
  • Legitimate completed: we also sent 10 real requests from nurses and a porter. The number is how many were delivered. A good defence must not block real work, so this should stay 10/10.
  • Containment rows: 4 extra tests about what happens after an attack has started. Explained below.
  • Retained service under attack: how much of the normal work still gets done while the hospital is being flooded. The formula is in the next card.
  • Robot / manual during attack: of the real tasks that got done during the attack, the first number is delivered by the robot and the second number is delivered by hand. Explained in the next card.

Retained service under attack

Retained service (%) = (real tasks completed during the attack ÷ real tasks completed in the same 30 seconds without an attack) × 100
  • The test: for seconds, nurses send real requests per second ( in total). At the same time a hacker floods the gate with fake requests per second. The gate can only check requests per second.
  • M0 to M3: the gate is overloaded and drops requests, including real ones. They completed of real tasks, so ÷ × 100 = %.
  • M4 and ALL: the circuit breaker spots the flood and cuts the hacker off. They completed of real tasks, so ÷ × 100 = %.

What "76 / 0" and "1 / 149" mean

  • / (M0 to M3): tasks were delivered by the robot and by hand.
  • / (M4 and ALL): task was delivered by the robot and by hand. The breaker cut off the robot zone after milliseconds. After that the robot could not be used, so nurses carried on in manual mode. attack requests were dropped without being checked.

Be careful with the 100%: it counts deliveries by hand on purpose, because the goal is that patient care continues. It does not mean the robot kept working. The robot only did task; the hospital kept going without it.

What each method is

No single method stops all 10 attacks. Only the combination (ALL) blocks every one.

Containment rows

C01–C04

The first defences try to stop one bad request at a time. Containment answers a different question: if an attack is already going on, can the hospital keep working? There are 4 tests (C01 to C04). They only make sense for a method that has a circuit breaker, which cuts the robot off when it sees an attack.

The cell x/y in the comparison table means: x tests passed out of y tests that could be run. M0, M1 and M2 show 0/1 because only one of the four tests (C03, the hacked robot) can be run on a system without a breaker, and it failed. M4 and ALL show 4/4.
